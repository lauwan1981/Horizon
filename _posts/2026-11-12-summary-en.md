### [Grok-built web apps publicly accessible due to default sharing settings](https://aihot.news/items/wlmgb3vb5ycgom7wq44felnin) ⭐️ 7.0/10

Claroc&\#x27;s security report analyzed 37,571 Grok-built web applications and found 35,578 \(94.7%\) are publicly accessible without authentication because the default publishing setting pre-selects &\#x27;Anyone with the link&\#x27;. Each app&\#x27;s independent subdomain is indexed into searchable passive DNS databases, making the exposed apps broadly reachable. The exposed content includes sensitive patient data and internal files from Grok-built projects.

rss · AIHot-Token羊毛 · Nov 11, 12:53

**「Background」** Many web application platforms default to public sharing when users publish projects, allowing anyone with a link to access deployed content. Claroc&\#x27;s report demonstrates how this default, combined with automatically generated subdomains, results in passive DNS indexing of Grok-built apps.

**「Impact」** Developers and organizations using Grok to build web applications face unauthorized exposure of sensitive data and internal files because the default &\#x27;Anyone with the link&\#x27; setting publicly indexes apps via passive DNS. Affected users should reconfigure sharing settings to restrict access to authenticated users and audit deployed apps for publicly indexed subdomains.
